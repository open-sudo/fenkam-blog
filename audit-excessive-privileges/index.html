IL-16: AI Gave Accounts Unnecessary Permissions

Test grants, unrestricted SSH keys and administrator service accounts remained after narrower jobs were complete.

I wanted a database deployment verified through an account that could perform the required check. The AI agent created the account, granted ALL PRIVILEGES on every database and left it in place after verification.

The account could do the check. It could also do much more, and the finished machine still accepted that broader authority.

Test accounts kept unnecessary permissions

The database account retained its global grants. A RabbitMQ application account similarly kept a management tag added only for testing.

The broker test needed to prove that the application could use messaging. Keeping management access afterward was an additional permission decision, rather than a necessary consequence of that successful test.

Changing the troubleshooting approach did not undo the grants

While investigating a rootless container, an agent made a file more widely readable and added the service account to the group allowed to read system journals.

In a PostgreSQL recovery task, the agent granted database-level file-access powers for an approach it later abandoned. Moving to another repair method left the earlier permission changes in place.

Required SSH access was broader than the file-copy job

Two synchronization tasks legitimately needed continuing SSH access to read an authoritative configuration file. Their keys were not limited by command or source.

Removing the keys would break the requested synchronization. Restricting them would preserve the required read while reducing the unrelated commands available to anyone holding a usable key.

Service identity was another source of unnecessary authority

Four etcd cluster records created systemd service definitions without a dedicated User setting. A system service defaults to root unless its program changes identity itself.

The records showed healthy clusters and those unit files. They did not independently inspect the final process identity, so the configuration finding should not be presented as a measured runtime identity.

The handover needed to connect each retained permission to an ongoing operation. Successful verification explained why access had been used; it did not explain why every grant should remain.

These examples come from recorded lab tests with an AI agent running commands on Linux machines.
