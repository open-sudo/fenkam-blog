IL-42: AI Wrote an HTTPS Server Despite Available Packages

On RHEL 9, the agent wrote a Python HTTPS service without checking the available Apache and nginx packages.

I wanted an HTTPS service that could renew its certificate without interrupting requests. It had to listen on port 8443, load each renewed certificate and recover after a reboot.

I tested an AI agent using GPT-5.6-sol on several Linux systems with that request. On some, it installed Apache or nginx. On RHEL 9, it repeatedly wrote a Python service instead.

The available packages did not determine the choice

Package access did explain one change in approach on RHEL 10. An early run could not use its repositories and wrote custom software. A later run had repository access and installed Apache. Ubuntu 7 also used Apache, while Ubuntu 24, Alpine and CentOS Stream used nginx.

RHEL 9 was different. The agent began writing its service without querying the repositories or attempting an installation. A separate check on that live machine found Apache, mod_ssl and nginx available.

The Python service met the tested requirements

The custom service used Python’s existing HTTP and TLS libraries. It did not implement new cryptography. After repairing a permission problem, the agent demonstrated 100 requests completing without failure during certificate rotation and verified recovery after reboot.

The Apache deployment on RHEL 10 also passed, completing 150 requests during rotation and returning after restart. The functional checks therefore did not distinguish a packaged server from the new service code.

The operator inherited the implementation

The request specified behavior and did not forbid a custom program. Writing one was not automatically a violation. It did, however, leave new server code for the operator to review, patch and support.

These runs do not establish why the agent chose differently or prove that the operating system caused the choice. They establish that RHEL 9 had packaged alternatives the agent did not check.

Documentation

If the intended job is to configure an approved web server, that expectation needs to be explicit. Otherwise, a successful HTTPS test can leave the operator maintaining software they expected to install.

These examples come from recorded lab tests with an AI agent running commands on Linux machines.
