IL-42: AI Wrote an HTTPS Server Despite Available Packages

On one RHEL 9.8 VM, an agent wrote a Python HTTPS service. Its first certificate rotation failed 78 of 80 requests before a permissions fix.

I asked an AI agent using GPT-5.6-sol to serve HTTPS on port 8443, renew its certificate before expiry, and keep answering requests as certificates changed. It had to retain the installed OS and kernel. The lab also checked recovery after reboot. The task specified behavior, leaving the choice of server to the agent.

The RHEL 9 run started with a single VM named node1, at 10.100.23.10. Its initial inspection recorded:

  • OS: Red Hat Enterprise Linux 9.8 (Plow).
  • Kernel: 5.14.0-687.20.1.el9_8.x86_64.
  • Services: systemd as PID 1; SSH was the only listening TCP service.
  • Software: Python 3 and OpenSSL were present; httpd and nginx were not found on the command path. The trace did not capture Python or OpenSSL version numbers.

The agent wrote a server before checking packages

The agent wrote autohttps-server.py without querying the repositories or trying to install a server. It reused Python’s HTTP and TLS libraries and ran as the unprivileged user autohttps. Its own integration code loaded a certificate-and-key bundle from /etc/pki/autohttps/active.pem for every new TLS connection, avoiding a service restart when that file changed. A root-run renewal script generated seven-day self-signed certificates; a systemd timer checked every six hours and renewed within three days of expiry. Recorded implementation.

A separate operator check during a RHEL 9 rerun found Apache 2.4.62 with mod_ssl and nginx 1.20.1 available in enabled repositories. That check was outside the executor’s commands; it does not show the agent considering those alternatives. Its command, package releases and provenance are preserved in the evidence.

The first renewal broke the working endpoint

The current bundle belonged to root:autohttps with mode 0640: root could write it and the service group could read it. After also correcting the certificate directory’s permissions, the agent obtained a successful HTTPS response and verified TLS handshake.

But the renewal script still created each replacement bundle with mode 0600. Renaming that new file into place replaced the readable file; it did not retain the old file’s permissions. On the first forced rotation, 78 of 80 local HTTPS requests failed. The diagnostic command then tried reading the new bundle as autohttps and received Permission denied. Because the server loaded the file on every new connection, the permission error prevented new TLS handshakes.

The repair passed the exercised checks

The agent changed the renewal script to create mode 0640 files and repaired the current bundle. On the next forced rotation, the served certificate serial changed and all 100 requests succeeded. The continuity loop used curl -k; a separate request verified the certificate against the local certificate file. After reboot, the service, timer, firewall rule and HTTPS response recovered, with the original OS and kernel intact.

These were short local tests, not a long-running production workload. Other runs of the same request used packaged servers: Apache on Ubuntu 7 and RHEL 10; nginx on Ubuntu 24, Alpine and CentOS Stream 10. The RHEL 10 Apache run completed 150 requests during rotation without failure. Those comparisons show different implementation choices, not that the OS caused the choice.

In production, renewal can be the outage trigger

The lab caught and fixed this defect before handoff. In a real deployment, the same defect could leave a newly installed endpoint healthy until a later scheduled renewal replaced its certificate bundle. New client connections would then fail TLS handshakes even though a new, unexpired certificate existed on disk. A successful installation check would have missed the event that broke access.

The broader issue is ownership. Python and OpenSSL still provide the protocol and cryptography implementations, but the operator now owns the custom request handler, certificate-loading code and their interaction with renewal permissions. Packaged servers also need correct renewal configuration; writing a server adds code to review, test and support.

If the job is to configure an approved server, name it. If a custom service is acceptable, make its maintenance owner explicit and test an actual certificate replacement as the service user before handoff. A passing endpoint test alone does not settle either decision.
