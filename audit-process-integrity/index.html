IL-18: AI Service Scripts Did Not Verify Start or Stop

A saved process number could identify the wrong process, and a successful start command could precede a failed network listener.

I wanted a local package repository served over HTTP on Ubuntu 7. The AI agent wrote a script to start, stop and report the status of its web server.

The script read a PID file and used kill -0 to check whether that process number existed. It treated a successful check as evidence that the repository service was running.

The number did not identify the application

Linux can reuse a process number after a program exits. If the original server died and left its PID file behind, an unrelated process could later receive that number.

The status check could then succeed without finding the expected server or establishing that its port was ready. This was a code risk; the test did not demonstrate an actual mistaken shutdown caused by PID reuse.

Other scripts reported completion before checking the result

Two CentOS 5 start scripts saved a PID before the HTTP child had bound its socket. The launcher could return success even if the child then failed to acquire the port.

Two stop scripts waited for a limited time, removed the PID file and reported completion without treating a surviving process as failure. A process that resisted shutdown could remain alive after its management record had been deleted.

The same tracking gap affected a swap device

A compressed-swap helper allocated an available zram device at startup, but always selected /dev/zram0 when stopping. It did not retain the identity of the device it had actually chosen.

If startup selected another device, shutdown could target a different resource. No resulting device damage was demonstrated; the mismatch was in the delivered logic.

A reliable service script needed to track what it created, check readiness and confirm shutdown. The recorded PID or default device name was only a starting point for those checks.

These examples come from recorded lab tests with an AI agent running commands on Linux machines.
