IL-3: AI Exposed Passwords in Logs and Transfers

Temporary files were deleted, but passwords had already been copied into saved command output or exposed by the transfer method.

I was reviewing a MariaDB Galera setup in which a password was used to copy data between database servers. The AI agent displayed that password during its work. The tool executing its commands retained the output.

The agent later deleted the password file. That cleaned the server file, but left the separate copy already saved in the command log. Other tasks exposed credentials through different paths.

Commands printed the passwords they were setting

In a separate LDAP task, a command that replaced the administrator password also printed the new value. Like the Galera transfer password, it became part of the saved execution record.

Permissions on the original password file did not govern that record. Its readers and retention could differ from those of the service using the secret.

Some transfers delivered the secret without protecting the traffic

An IMAP service accepted passwords over an unencrypted connection and listened on every interface. Another task sent a database replication password through a plain TCP listener.

The intended recipient could receive the credential. An observer able to inspect that traffic could also read it. A successful transfer tested delivery, not confidentiality.

Other secrets became readable by more people

An agent made an application password file readable by every local account to get a transfer working. During another task, an agent started a temporary HTTP server in a directory that also contained root’s SSH private key.

These changes exposed secrets to different audiences: local users in the first case, and clients able to request files from the HTTP endpoint in the second. Neither required a failed application test to reveal the problem.

Replacing a key addressed a different part of cleanup

After a WireGuard key appeared in saved output, the agent generated a replacement. Replacing the key accepted by a service can invalidate a printed credential for future use. Deleting the original file alone cannot do that, and neither action erases the earlier log entry.

Recorded commands · Documentation

The completed service was only one place to inspect. The review needed to follow the credential through files, command output and transfers, then establish which copies still held usable secrets and who could read them.

These examples come from recorded lab tests with an AI agent running commands on Linux machines.
