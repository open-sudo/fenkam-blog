The Task Finished. Its Credentials Had Already Escaped.

Secrets appeared in execution output, plaintext transfers, permissive files and temporary web servers.

An AI agent finished setting up a database, but its command output contained a live password. Deleting the temporary password file afterward could not remove the copy already saved in the transcript. Other tests exposed secrets through network transfers and file permissions. The common problem was where the secret went while the work was being done.

The execution record became a secret store

A Galera setup printed its state-transfer password into captured output. In a directory-server task, a password replacement command also printed the live administrator password. Protecting the final password file did not undo those transcript copies. (first trace; second trace.)

Diagnostic output can retain a credential long after the command has finished.

Transfers exposed the content or skipped endpoint authentication

One IMAP service allowed plaintext password authentication on all interfaces. A separate replication setup moved its password through a plaintext TCP listener. The transfers worked, but the recorded paths lacked the intended confidentiality. (first trace; second trace.)

A transfer can complete and still leave the sender without the intended confidentiality or assurance about the recipient.

File permissions and directory scope widened access

An application password was made world-readable to get a transfer working. In another task, a temporary HTTP server exposed a directory containing root’s SSH private key. These are different exposure paths: local file access and network-served content. (first trace; second trace.)

A permission change made to get a transfer working can make a private key readable by unrelated local accounts.

Corrective rotation matters

After a WireGuard key appeared in captured output, the agent explicitly rotated it. That response matters: the old printed value no longer represents the final credential. Rotation limits the remaining risk even though it cannot remove the earlier disclosure. (commands.)

The history also contains a case with an explicit response to disclosure.

What should an administrator check?

The handover needs to account for where sensitive values traveled, not only which temporary files remain. Captured output, copied files and network transfers require different cleanup. A credential exposed outside its intended boundary may need replacement; deleting its staging file alone does not revoke it.

Evidence. These examples come from recorded tests in which an AI agent received a Linux administration task and command access to isolated machines. The source extract includes all 45 cases grouped under this topic, their commands and assessment references, and the limits of each finding. The article distinguishes observed failures from risks identified in code and behavior that was not tested. No production attack is claimed. Original records are available in InfraSet.
