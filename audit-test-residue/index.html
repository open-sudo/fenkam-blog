AI Left Test Data, Listeners and Simulated Outages in the Deployment

Synthetic backups, test listeners, configuration markers and simulated repository outages survived verification.

An agent proved that a backup retention rule worked by creating artificial old backups. It then left them beside the genuine archive. Other tests left listeners running or blocked normal package repositories. The demonstration succeeded, but part of the demonstration became operational state.

Imagine a theatre crew leaving rehearsal props mixed with the real emergency equipment after opening night. The rehearsal may have worked, but the next person cannot safely treat everything as operational. Synthetic backups, test listeners and outage simulations similarly need removal or clear separation from the system being handed over.

Retention tests left invented backup history

An agent created artificial historical backups beside genuine archives. Another retention test left four synthetic dated copies in the final listing. Creating test history was useful for the test; keeping it in the real backup directory made later interpretation harder. (first trace; second trace.)

Copying an archive under older dates can exercise a deletion rule.

A source-of-truth file became a test fixture

One verification replaced authoritative application configuration with test data. Another left duplicate debug settings and markers that the synchronization system then distributed. The sync could work correctly while carrying the test’s residue. (first trace; second trace.)

Appending markers or replacing application configuration can prove a synchronization mechanism.

Test servers kept listening

A synthetic TCP listener on the PostgreSQL port remained after a firewall demonstration. A separate alias-policy test left its Python listener running. Neither remaining process was the production service the port number might suggest. (first trace; second trace.)

A synthetic database-port listener or throughput server can be appropriate during a bounded check.

An injected outage was never ended

An Alpine local-repository test left a hosts-file block of the normal CDN in place. An Ubuntu demonstration retained a global APT proxy that blocked normal repositories. The simulated outage became a continuing package-access problem. (first trace; second trace.)

What should an administrator check?

Useful cleanup restores the pre-test inputs and removes temporary mechanisms, not just files with obvious temporary names. Verification artifacts retained intentionally should be labeled and separated from live configuration and genuine recovery history. A successful test can otherwise become the cause of a later operational surprise.

Evidence. These examples come from recorded tests in which an AI agent received a Linux administration task and command access to isolated machines. The article distinguishes observed failures from risks identified in code and behavior that was not tested. No production attack is claimed. Original records are available in InfraSet.
