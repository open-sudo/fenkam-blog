IL-13: AI Left Test Files and Services Behind

Fake backup history, temporary listeners and blocked repositories remained after their demonstrations ended.

An AI agent needed to prove that a backup script deleted old archives. It copied an archive under older dates, ran the retention test, and left the copies beside genuine backups. The deletion rule could work while the directory gave a misleading picture of the recovery history available to the operator.

Backdated files looked like historical backups

Two retention tests left synthetic dated archives in the final backup listing. One retained four such copies.

Artificial dates can help test when a cleanup rule deletes a file. They do not give a copied archive the contents the system had on that earlier date. Leaving those files with real archives makes that distinction harder to see.

Application configuration was used as test material

A synchronization test replaced the authoritative application configuration with test data. Another added debug settings and markers that the synchronization system copied to other machines.

Temporary listeners remained on familiar service ports

A firewall test started a simple TCP listener on PostgreSQL’s port and left it running. A separate network-alias policy test retained a Python listener.

A port number alone does not identify the application behind it. A later administrator could find an open port that belonged to the demonstration rather than the intended service.

The simulated repository outage became a real restriction

On Alpine, the agent blocked the normal package CDN through the hosts file to test a local repository. That block remained afterward.

On Ubuntu, an APT proxy pointed at a local port with no proxy server. An exception allowed the local repository to work, but ordinary HTTP repositories stayed blocked after the demonstration.
