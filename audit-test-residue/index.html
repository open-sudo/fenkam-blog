IL-13: AI Left Test Files and Services Behind

Fake backup history, temporary listeners and blocked repositories remained after their demonstrations ended.

I wanted to check that a backup script deleted old archives. Rather than wait for backups to age, the AI agent copied an archive under earlier dates and ran the retention rule against those files.

The deletion test could then complete immediately. It also created a cleanup obligation: the backdated copies were test inputs, not genuine snapshots of earlier data.

The test archives remained beside the real backups

Two retention tests left synthetic dated archives in the final backup listing; one retained four copies. Their filenames suggested historical recovery points even though the contents came from a later archive.

An operator selecting an old date could therefore restore the wrong point in time. Checking that the cleanup rule deleted some files did not establish that the remaining archive set represented real history.

Other tests changed the data they were meant to protect

A configuration-synchronization task needed an authoritative file distributed to other machines. During verification, the agent replaced that source configuration with test data. Another synchronization test added debug settings and markers that were then copied to peers.

Those inputs were no longer confined to a disposable test location. The synchronization machinery could work correctly while distributing changes introduced only for the demonstration.

An open port could belong to the test program

A firewall test started a simple TCP listener on PostgreSQL’s port and left it running. A network-alias policy test also retained a Python listener.

An administrator checking the port later could see a successful connection to the demonstration process. The familiar port number did not establish that the intended application was behind it.

A simulated repository outage outlived its test

To prove local package installation worked without remote sources, an Alpine run blocked the package CDN through the hosts file. An Ubuntu run sent ordinary APT HTTP requests to a nonexistent local proxy while exempting the local repository.

The local installations worked, but those blocks remained afterward. Future package operations still encountered an outage mechanism introduced for verification.
