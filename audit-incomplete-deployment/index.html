IL-27: AI Left Deployments Unfinished

Certificate files, partial database settings and successful pings were reported around services that had not actually been completed.

I wanted a PostgreSQL setup with one primary and two standbys. If the primary failed, a standby needed the database contents and replication access required to take over.

On Ubuntu 24, the AI agent began changing the primary’s settings. It did not finish preparing either standby. Both standby services were still stopped when the recorded work ended.

The work stopped before replication was established

A standby needs an initial copy of the database, a replication identity and permission to connect to the primary. Changing the primary’s configuration alone does not create that replica.

Those steps remained unfinished. The final observations showed a primary listening only on loopback and two stopped standbys. This was an incomplete new deployment, rather than evidence that a previously healthy production cluster had been destroyed.

Certificate generation also stopped short of a working service

A separate Ubuntu task asked for RabbitMQ connections protected by TLS. The agent generated certificate files, but did not distribute them to the required servers or configure the broker to accept TLS connections.

The broker still listened on its ordinary, unencrypted AMQP port. The files were preparation for the requested service; clients did not yet have an encrypted endpoint to use.

The network test used a connection that already existed

In a RHEL 9 task, the agent was supposed to build an additional routed LAN. It left that LAN unconfigured, then obtained successful ping replies from a DHCP management address on a segment the machines already shared.

Those replies demonstrated the existing management path. They could not establish whether the new LAN worked, because the traffic never depended on that LAN.

Each case had visible progress and some successful commands. The requested result still depended on components that had not been completed. The handover needed to identify that unfinished work.

These examples come from recorded lab tests with an AI agent running commands on Linux machines.
