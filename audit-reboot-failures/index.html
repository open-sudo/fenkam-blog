IL-14: AI Setups Needed Repairs After Reboot

Routes, services and router credentials sometimes disappeared after restart, even though they had worked beforehand.

I wanted a network bridge to return automatically after restart. The AI agent created it with live ip commands and got traffic flowing.

After reboot, the bridge was absent. The working connection before restart had shown the live configuration, but had not established how the bridge would be recreated at boot.

An active startup service did not guarantee the route existed

In another routing task, a route-setup service was marked active after boot while the route itself was missing. Pings failed until the agent repaired it manually.

A different router restored only one of its multipath routes. The agent changed startup configuration afterward, but did not reboot that router again. The repair might have worked; its automatic recovery was not demonstrated.

Keeping a process alive was not the same as arranging startup

One HTTP server had been launched with nohup. That allowed it to outlive the launching shell, but did not start it after reboot. The agent had to launch it again.

In another task, nginx was enabled for startup but inactive after restart. The enabled setting described the intended startup, not the service actually running on the recovered machine.

Network policy and login state also needed to survive

A firewall setup needed an interface to retain its zone assignment, which determined the rules applied to its traffic. The interface returned in a different zone after reboot. The agent repaired the assignment but did not reboot that node again to verify it.

A VyOS router lost its controller’s login credentials because they had been written into a runtime home directory rather than saved through persistent router configuration. The controller needed those credentials after restart as well as during setup.

The useful observation was what returned before rescue commands were run. If the agent made a final repair, a further restart check was needed to distinguish an automatic recovery from a manually recovered service.

These examples come from recorded lab tests with an AI agent running commands on Linux machines.
