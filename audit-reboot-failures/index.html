IL-12: AI Setups Needed Manual Repairs After Reboot

Routes, services and router credentials sometimes disappeared after restart, even though they had worked beforehand.

An AI agent created a network bridge with live ip commands. Traffic worked, but the bridge disappeared after the machine restarted. Another route returned only after the agent entered a command again. The request required automatic recovery; these tests showed a need for manual intervention.

Imagine a shop’s automatic shutters opening only after the owner arrives and cranks them by hand each morning. The shop can open, but the automatic mechanism has not been demonstrated. Routes and services restored through post-reboot commands similarly show that recovery is possible, without establishing automatic startup.

Live networking commands did not survive startup

A bridge and an equal-cost multipath route worked before reboot but were not restored automatically. Commands that change the running network do not necessarily update the configuration read at startup.

An active startup service still left the route missing

One machine reported its route-setup service as active, yet the route was absent and pings failed until the agent repaired it manually.

Another router restored only one of its multipath routes. The agent changed its startup configuration afterward but did not reboot that router again. The change might have fixed the problem; that final recovery test was missing.

A web server had to be started again

One HTTP server had been launched with nohup. That kept it alive after the launching shell ended, but did not arrange a start after reboot. The agent had to launch it again.

In another task, nginx was enabled for startup but was inactive after restart. An enabled setting described what was intended to start; it did not explain why the service was not running.

Router access and firewall settings also had to persist

A firewall interface returned in the wrong zone after reboot. The agent repaired the assignment but did not restart the affected node again to verify the repair.

A VyOS router lost the credentials used by its automation controller because they had been written into a runtime home directory instead of saved through the router’s persistent configuration.

After the final fix, restart the affected machine and observe it before entering any rescue commands. Record which parts returned on their own. A successful manual recovery is useful, but it is not automatic recovery.

These examples come from recorded lab tests in which an AI agent could run commands on Linux machines. Case evidence. The source records contain the commands and the observations used here.
