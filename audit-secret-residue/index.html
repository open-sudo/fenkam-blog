The Deployment Left Extra Copies of Its Secrets

Temporary keys, password helpers, superseded configurations and test fixtures survived cleanup.

The certificate was installed and the service worked. Extra private keys still sat in the directories used to stage the deployment. This happened with passwords, broker credentials and test fixtures too. Not every copy was readable by other users, but each unnecessary copy became another place that needed protection.

Distribution created a second key collection

A database certificate deployment retained its CA signing key in temporary staging. An mTLS check left a staging tree containing CA and client private keys. These copies carried different authority from an ordinary public certificate. (first trace; second trace.)

Installing the final certificate does not remove the issuing key, client test identity or bundled transfer copy used to get it there.

Cleanup missed one host or an earlier copy

Replication-password cleanup missed the machine where the transfer originated. A broker task missed both the original host and an abandoned copy. Multi-host cleanup needed to follow every copy, not just the receiving side. (first trace; second trace.)

A multi-node cleanup can look complete from the receiving machines while the originating host still has the password.

Helpers and diagnostic changes kept credentials embedded

Galera staging configurations retained authentication material. Broker helper scripts kept live passwords embedded in their commands. A secret can survive in a useful-looking helper even after an obvious password file is removed. (first trace; second trace.)

Secrets can survive in configuration fragments and scripts rather than files named password.

Old generations and test fixtures accumulated

Certificate rotation left superseded key directories behind. A privacy exporter kept copies of its private input in test fixtures. Successful replacement or redaction did not remove the material used to verify it. (first trace; second trace.)

What should an administrator check?

The appropriate cleanup starts with an inventory of copies and their owners. It distinguishes the active service credential, an intentional recovery copy and abandoned staging. Protected residue increases the number of places that need protection; evidence of broader readability or transmission is a separate, stronger claim.

Evidence. These examples come from recorded tests in which an AI agent received a Linux administration task and command access to isolated machines.
