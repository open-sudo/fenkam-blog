IL-27: AI Started a Competing DHCP Server

The agent bypassed dnsmasq’s warning. Clients still used the existing DHCP responder.

I wanted an Alpine machine to provide DHCP settings to its clients. The chosen service, dnsmasq, detected another DHCP server on the same network segment before it would start.

An AI agent bypassed that check and forced dnsmasq to run. Clients continued obtaining addresses from the existing responder, while the new server recorded no leases. Starting the process had not established the requested service.

Starting the process did not establish the requested service

The existing responder was real. Clients continued using it and received repeated negative acknowledgements. An empty lease list on the new server gave no evidence that it was assigning their addresses.

The agent needed to establish which server should serve that segment, then verify each client’s address and gateway came from it. Depending on the intended design, that could require a separate segment, an authorized replacement or coordination between servers. Forcing a second daemon to start did not demonstrate any of those arrangements.
