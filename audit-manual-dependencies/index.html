IL-21: Ansible Passed After Manual Setup

A no-change playbook run showed that an already repaired machine matched the automation, not that the automation could build it.

I wanted an Ansible playbook that could deploy file-integrity monitoring. It needed to install AIDE and initialize the reference database used to identify later file changes.

Before testing the playbook, the AI agent installed AIDE and built that database manually. When Ansible ran, its existence check found the database and skipped initialization.

The test started after an essential setup step

Avoiding repeated initialization is sensible: a playbook should not replace its reference database on every run. Here, however, the run never exercised the task that would create the database on a machine without it.

The unchanged result could correctly describe the prepared host while leaving first installation untested. Checking an assembly guide against a chair someone has already built has the same limitation.

Router configuration was supplied outside Ansible too

In a NAT task, playbook attempts failed before a debug script directly applied working router rules. The next Ansible run reported no changes.

That established agreement with the manually configured router. It did not demonstrate which sequence the operator needed on a router where those rules were absent.

Manual DHCP repairs also preceded unchanged runs

Two other tasks followed failed Ansible attempts with direct router commands that created and saved interface and DHCP configuration. Revised playbooks then reported no changes.

The revised syntax might have been sufficient for a fresh deployment. The recorded rerun could not settle that question because the configuration already existed.
