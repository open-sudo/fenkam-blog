Illusion of Done #1: AI Built Crazy Software Instead of Configuring Apache or Nginx

A request for two websites became a custom Python HTTP server. It passed the tests, but left the operator with a codebase to maintain.

When I asked an AI sysadmin to put two websites on a machine, I expected Apache or nginx configuration. In one Ubuntu 7.10 task in InfraSet, I found that the agent had written its own HTTP server instead. Both websites worked, and the task received a perfect functionality score.

I chose this as the first example in my Illusion of Done series, following the earlier article. The intent of this series is to give sysadmin recognizable failure modes to guard against.

What happened

Here was the original task prompt:

The documentation and purchasing teams need separate websites on node1, sharing TCP port 8080. Requests for docs.branch.test should serve the supplied docs tree; requests for orders.branch.test should serve the orders tree. An unknown Host header should receive an error rather than either team's content. The approved content is staged under /srv/legacy2/name-based-web-tenants; preserve it.

Keep the installed operating-system release and kernel; use software compatible with this legacy platform.

The agent created /usr/local/sbin/name-based-web-tenants.py. The execution log recorded the command and source code: it used Python’s HTTP server classes, added hostname routing and file-path handling, and installed startup configuration so the service returned after a reboot.

The evaluation report recorded both sites returning the expected content, unknown hosts and cross-tenant file requests receiving errors, and unchanged content checksums. The service survived a reboot. That earned it 1.0 for functionality.

The task did not require Apache or nginx or forbid custom code. I had not established that either package was readily installable on this old system. So the agent met the stated requirements. What surprised me was how much new software came with the result.

The server became my problem

That was what I meant by “crazy software”: I had asked for two websites and ended up with a custom web server. Any future fault would have required someone to investigate that code, and any change would have needed testing. Accepting it meant deciding where the source belonged, who maintained it and how fixes were deployed.

The passing tests did not answer those questions. They showed that the requested behavior worked and recovered after a restart. They did not establish how the server handled sustained load, slow clients or malformed requests. Those properties remained untested; the run had not demonstrated defects in those areas.

Custom software might have been an acceptable choice, but that choice needed to be deliberate. The illusion of done lay in accepting the successful result without noticing the maintenance job attached to it.

What needed checking

Before accepting the result, I needed to identify the process listening on the port and the command used to start it. In this case, the execution log led to the new Python server. The key question was which persistent programs the agent had written and why. Reviewing those changes showed whether it had configured an existing service or implemented one.

A complete handover would have included the source, instructions for restarting or removing the service, and a clear account of what had been tested. Someone also needed to take responsibility for maintaining it.

I could also have set a boundary upfront: require an approved web server and an explanation of any blocker before the agent wrote a replacement. That instruction had been absent from this task.

I had wanted two working websites. What I also needed to understand was how much software I would have to keep working after the agent left.

Run details. Ubuntu 7.10, InfraSet scenario 8220, task name-based-web-tenants, batch 2026-10-03__01-23-07. The executor and separate LLM evaluator used gpt-5.6-sol at high reasoning effort. Evidence was linked to a fixed commit. I examined one recorded case and did not measure how often this happened.
