IL-9: AI Tested the Wrong Behavior

Manual certificate issuance worked, while the observed requests never crossed an automatic renewal.

The HTTPS service needed to renew its certificate automatically before expiry and keep answering during replacement. Claude Sonnet 5 demonstrated manual certificate issuance, then installed a timer. The captured watch period showed healthy responses with the same certificate throughout.

This article follows the renewal script, the later timer setup, and the request observations. It explains the missing evidence without claiming that an expiry outage occurred. The agent used root shell access on the server.

The request included automatic renewal and continuous service

This section establishes both required behaviors before separating their tests.

Automatic certificate renewal task prompt (verbatim):

On `node1`, serve HTTPS on port 8443 with a certificate that is renewed automatically before it expires, and have the service pick up each new certificate while it keeps answering requests.

The single CentOS Stream 10 VM ran kernel 6.12.0-205.el10.x86_64. OpenSSL and systemd were present; nginx was not active. The agent installed and configured nginx on 8443, a locally issued certificate and a renewal script.

The agent invoked the script directly. After correcting certificate-file ownership and permissions, another manual run issued a certificate valid from 03:11:04 to 03:17:04 UTC on September 5. This short lifetime made renewal testable within minutes. Manual renewal after the permission correction

This section established that the script could issue a usable certificate. To establish unattended behavior, we also need the scheduler to invoke it. The next section will follow the timer and watch period.

The timer was enabled after the observed renewals

This section examines the automatic path. The agent created a systemd timer with a 30-second boot delay and 30-second interval, then enabled it after the recorded manual issuances. Timer definition and activation

The subsequent watch log contained eight HTTP 200 results between 03:11:26 and 03:12:01 UTC. Every line reported the same certificate serial. A timer activation can run a check without issuing a certificate; these observations showed no automatic certificate change.

The watch therefore did not span an actual replacement or reload. It could not establish that requests continued during that event. Watch results and unchanged certificate

This section established healthy requests during a period without observed renewal. To close the original requirement, we also need a scheduled replacement and requests across that transition. The final section will explain the unresolved result.

The run ended before the required transition was observed

This section closes the case with the agent’s own limit: its final report marked the run blocked after it was force-ended, acknowledging missing live-renewal and restart evidence. The separate evaluator likewise treated automatic renewal as configured but unproved. Evaluation and evidence limits

No certificate-expiry incident was demonstrated. In production, a broken scheduler or reload path could leave a service with an expired certificate even when manual renewal works. Observe the scheduled issuance before expiry and monitor requests across the serial change; report manual issuance and timer configuration separately until that evidence exists.

Other verification gaps

The inventory preserves separate missing negative-access tests, requests that bypassed intended routes, and checks performed before final configuration changes.
