IL-39: The Same Task Left Different Server Configurations

The same repository demonstration led to core-library upgrades, an older RPM stack, or a much smaller installation.

I wanted a local package repository to serve installations while remote repositories were unavailable. I gave that task to an AI agent three times on RHEL 10.

All three attempts demonstrated a working local installation. The package changes, however, left different configurations to maintain afterward.

Building a demonstration package led to core-library repairs

One agent chose to build an RPM for the demonstration. Installing its prerequisites added 33 packages and upgraded nine. A new RPM cryptography component needed OpenSSL symbols the machine lacked, leaving RPM and DNF unusable.

The agent recovered by extracting newer OpenSSL libraries into the live system, then reconciling the packages through a transaction that bypassed signature checks. The machine rebooted and dnf check passed. It was not left with unexplained manual library copies, but its cryptographic libraries and policies had changed.

A second run restored a compatible older RPM stack. A third previewed its prerequisite transaction and demonstrated the repository with an existing tree package. That transaction added only two packages and avoided the build tools and core-library repair.

The comparison does not isolate a cause

The repository request was the same, but later runs also had instructions to preserve state, minimize changes and verify security. The reasoning settings differed too. These were separate executions with different instructions around the task, not an experiment holding every setting constant.

Other releases left different update arrangements

RHEL 9 used Apache and an existing tree package. AlmaLinux used tree and removed extra downloaded dependencies. Alpine built a signed APK repository, served it through lighttpd and removed its temporary block on remote sources.

Other runs retained changes outside the demonstration: CentOS Stream left normal repositories moved aside; RHEL 7 retained a source with signature checking disabled after using CentOS Vault; Ubuntu kept an APT proxy blocking ordinary HTTP repositories.

The next administrator needed more than an installation result

A later update would encounter those source settings and package versions. No production patching failure was observed here, but the operator still needed an accurate account of the differences.

Approved package sources and service choices can limit that variation. The final review also needs the packages added or upgraded, repository edits and any repairs to core components.
