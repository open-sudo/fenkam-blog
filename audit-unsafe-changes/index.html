IL-11: AI Repairs Changed Unrelated Accounts and Services

Account edits, package recovery and storage helpers affected credentials, core libraries and unrelated services.

While configuring database roles, an AI agent failed to generate passwords because OpenSSL was missing. The following commands still ran and temporarily cleared the passwords. Other repairs similarly changed authentication, networking or storage beyond the intended operation.

Account changes ran before their inputs were checked

The database-role passwords were later corrected. A separate LDAP task activated a malformed administrator-password hash before repairing it. In both cases, a failed preparation step reached live authentication settings.

Package recovery replaced libraries used by the whole machine

A local-repository task copied an incompatible RPM library over the live version, then reversed that attempt. It also manually replaced OpenSSL libraries before reconciling them through package management.

Another agent force-killed apt and dpkg processes and removed lock files. That machine eventually had consistent package state, but interrupting an installation could leave partial changes or allow conflicting transactions.

A narrow task changed unrelated access

BGP configuration work removed the address from an existing Docker bridge and forced it down on two routers. The record did not establish a resulting container outage or show that BGP required the change.

On Alpine, a cron restriction also limited access to a shared privileged helper used by su, passwd and other tools. The agent had seen those other uses but did not test or report their loss for ordinary users.

Storage scripts handled failure badly

Generated boot code for loop-backed storage was followed by observed filesystem corruption. A separate snapshot helper could exit after a failed operation without unfreezing the filesystem.

The second problem is a failure path in the script: a snapshot error could leave applications unable to write until someone unfreezes the filesystem.

Credential cleanup also changed what the operator would receive

A root password was changed after its generation step failed, before a corrective update restored a healthy machine. An FTP setup introduced an unnecessary password relay and rotation, changed the handover credentials, and left earlier SSH keys behind.

Inspect the changed accounts, files and services after each repair. A command’s exit status does not validate everything it changed.

These examples come from recorded lab tests with an AI agent running commands on Linux machines.
