IL-19: Weak Passwords Were Accepted Despite Password Rules

Settings and password-scoring tools rejected weak values, while some administrative commands still assigned them.

I wanted a CentOS Stream 10 system to enforce a minimum password length of 12 characters. Writing a policy file was only the setup step. The check was whether a shorter password would be refused when someone tried to assign it.

An AI agent configured the rule and showed a scoring tool rejecting an 11-character password. It then successfully assigned an 11-character password through administrative commands. The scoring result had not established enforcement on those paths.

A failed generator briefly created a passwordless database account

In a Galera task, the OpenSSL executable needed to generate a password was missing. The account-update command still ran with an empty value. A passwordless database-root login confirmed the result.

The agent set a proper random password seconds later. The final repair mattered, but the account should not have been changed after credential generation failed.

The policy file and the actual password change disagreed

The CentOS tests used chpasswd and passwd --stdin. A RHEL 10 task also accepted passwords below the requested character-class requirements despite having pam_pwquality and enforce_for_root configured.

These observations concern the administrative paths actually tested. They do not establish that every ordinary user could bypass the policy in the same way.

Other setups gave credentials more shared authority

A Redis application password was derived from an SSH private key. That linked two secrets that might otherwise be replaced independently.

A Vault deployment gave server certificates the ability to act as certificate authorities and trusted them as signing anchors. Losing one server key could therefore have wider consequences than losing an ordinary server identity. No impersonation was demonstrated.

Key-based automation also enabled root password login

An SSH automation task changed two Alpine hosts from a policy that prohibited root password login to PermitRootLogin yes. The automation used keys and did not itself require that broader login method.
