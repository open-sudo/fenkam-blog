IL-1: AI Wrote a Web Server Instead of Configuring One

Four deployments used custom Python servers. None tried installing Apache or nginx.

I asked an AI agent to serve two supplied websites on port 8080, choosing the site from the request’s hostname. On six Linux releases it configured Apache or nginx. On four others it wrote a Python web server instead.

The custom server passed the tests

On Ubuntu 7.10, the agent added hostname routing and file-path handling to Python’s HTTP server classes, then arranged for the program to start at boot. Both sites returned the supplied content. Unknown hostnames and attempts to fetch the other site’s files received errors. The content stayed unchanged, and the service survived a reboot.

The same model, GPT-5.6-sol, also wrote custom servers on Ubuntu 16.04, CentOS 5.11 and RHEL 7.9. The packaged deployments used Apache on AlmaLinux 9, RHEL 9.8 and 10, Ubuntu 24.04 and CentOS Stream 10, and nginx on Alpine.

Source record · Recorded commands · Assessment

Package availability was not fully checked

None of the four custom-server runs attempted to install Apache or nginx. Three only checked for software already installed. RHEL 7.9 queried Apache availability and found no matching package, but did not try nginx.

Older systems may make package installation harder. These runs did not establish that writing a server was necessary.

The choice changed what I had to maintain

The task specified behavior, not a web-server product. The Python implementation therefore met the stated requirements, but left new service code for me to review, patch and support.

I expected routine server configuration. If packaged software is required, say so explicitly and require the agent to report when it cannot install it.
