IL-1: AI Wrote a Web Server Instead of Configuring One

Four deployments used custom Python servers. None tried installing Apache or nginx.

I wanted two supplied websites served from one machine on port 8080. A request’s hostname had to select the right site; an unknown hostname had to receive an error. The existing operating-system release, kernel and site contents were to stay in place.

I tested an AI agent using GPT-5.6-sol on ten Linux releases. I expected a web-server configuration. On six releases it configured Apache or nginx. On four, it wrote a Python server.

The custom server satisfied the functional checks

On Ubuntu 7.10, the agent used Python’s HTTP server classes and added hostname routing, file-path handling and startup configuration. Both sites served the supplied pages. Unknown hostnames and requests for the other site’s files received errors, the content checksums stayed unchanged and the service survived reboot.

The agent also wrote custom servers on Ubuntu 16.04, CentOS 5.11 and RHEL 7.9. The packaged deployments used Apache on AlmaLinux 9, RHEL 9.8 and 10, Ubuntu 24.04 and CentOS Stream 10, and nginx on Alpine.

Source record · Recorded commands · Assessment

The records did not establish that a custom server was necessary

None of the four custom-server runs tried installing Apache or nginx. Three checked only software already installed. On RHEL 7.9, an Apache availability query found no matching package, but the agent did not try nginx.

Older systems can make installation harder. These records did not show the agent exhausting the packaged alternatives before writing software.

The passing result left code to maintain

The prompt specified behavior rather than a web-server product, so the custom implementation met the wording. The unexpected part was the maintenance responsibility: new request-handling code to review, patch and support.

The tests answered whether the supplied sites worked. They did not make the Python implementation equivalent to installing an established server.

If the intended work is routine configuration of approved software, that needs to be stated. The agent should report when that software is unavailable, rather than silently making ownership of new server code part of the handover.
