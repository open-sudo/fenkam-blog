IL-19: AI Left Unrequested Network Services Running

HTTPS worked, but plain HTTP, discovery or administration services sometimes remained available too.

I wanted an HTTPS site running on a server. The AI agent installed and configured the web software, then fetched the encrypted page successfully.

The ordinary HTTP site was still listening as well. The HTTPS request proved that the new endpoint worked, but had not told me what else the installation made available.

Package installation started services beyond the requested one

A file-integrity task introduced an SMTP listener when its tools were installed. A print-archive task intended for local use enabled network discovery on all interfaces.

Those services could come from dependencies or package defaults. They still changed the network-facing software the administrator inherited, even though they were not the endpoint being tested.

Management ports needed their own review

A broker deployment enabled a management interface with default administrator credentials. A Kerberos setup retained remote-administration services the requested application did not need.

An application request would not test those interfaces. Their bind addresses, firewall access and authentication had to be examined separately to establish who could use them.
