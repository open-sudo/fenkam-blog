LLM Wrote New Software Instead of Configuring Apache or Nginx

Illusion of Done #1: A request to implement two websites became implementation of a custom Python HTTP Server. And it passed the functional test.

In today illusion, I asked GPT 5.6-sol to develop two websites on the same machine. I expected it would use virtual hosts on a normal webserver. This is what happened on Ubuntu 24 and 16. On Ubuntu 7.10, however, the agent implemented a new HTTP server on which it then hosted the two websites.

This is the first article in the Illusion of Done (IOD) series. The intent of this series is to give sysadmins recognizable failure modes to guard against.

What happened

The original task stated:

The documentation and purchasing teams need separate websites on node1, sharing TCP port 8080. Requests for docs.branch.test should serve the supplied docs tree; requests for orders.branch.test should serve the orders tree. An unknown Host header should receive an error rather than either team's content. The approved content is staged under /srv/legacy2/name-based-web-tenants; preserve it.

Keep the installed operating-system release and kernel; use software compatible with this legacy platform.

I ran the exact same task on numerous operating systems: Alpine Linux, Alma Linux 9, RHEL 10, RHEL 9.8, RHEL 7.9, CentOS 5.11, Ubuntu24.04, Ubuntu16.04, Ubuntu7.10, and CentOS Stream 10. On Alpine Linux, the agent installed Nginx while on Alma Linux 9, RHEL 10, RHEL 9.8, RHEL 7.9, Ubuntu24.04, and CentOS Stream 10, the agent chose to install Apache web server. Suprisingly, on all other releases, a new python web server was implemented. We focus on the Ubuntu 7.10 in this article. The implemnattion is at: name-based-web-tenants.py. The execution log recorded the command and source code: it used Python’s HTTP server classes, added hostname routing and file-path handling, and installed startup configuration so the service returned after a reboot.

The evaluation report recorded both sites returning the expected content, unknown hosts and cross-tenant file requests receiving errors, and unchanged content checksums. The service survived a reboot and earned it 1.0 for functionality.

The agent met the stated requirements. Never would I have imagined that the agent would implement a completely new webserver.

What could have been done differently

One may be tempted to conclude that the behavior is triggered by the age of the operating system. However, the traces show that in many cases, the agent did not try to install the webserver. It simply checked if there was a web server installed and proceeded with its own implementation (see Ubuntu 16.04). In the case of RHEL 7.9, it tried to install a conventional web server but there was no repository available.

Overall the lesson is that of underspecification. The prompt left the agent too much room for interpretation and speculation.

Run details. Ubuntu 7.10, InfraSet scenario 8220, task name-based-web-tenants, batch 2026-10-03__01-23-07. The executor and separate LLM evaluator used gpt-5.6-sol at high reasoning effort. Evidence was linked to a fixed commit. I examined this Ubuntu 7.10 case alongside the Ubuntu 24.04 run of the same task; I did not measure how often this happened.
